# flutter_workers

A Flutter example for [`volley_workers`](../../packages/volley_workers). One set
of annotated functions (`lib/workers.dart`) runs as **web workers** on the web
and as **isolates** on mobile and desktop; the UI code (`lib/main.dart`) is the
same on both.

It demonstrates all three primitives:

- **Coroutine** (`countPrimes`): a one-shot job, started from the
  "Count (coroutine)" button.
- **Actor** (`analyze`): a long-lived worker, spawned on first use and reused by
  the "Analyze (actor)" button.
- **Singleton** (`RunLog`): a shared counter the actor bumps on every run. On
  the web it lives on the UI page and the worker reaches it by message
  passing, so the run number in the result is shared across the page and the
  worker.

## Run it

```
flutter pub get
tool/build_workers.sh      # generates workers.gen.dart, compiles the web workers
flutter run -d chrome --no-web-resources-cdn
```

`--no-web-resources-cdn` is optional; it bundles CanvasKit instead of
downloading it, which helps offline or behind a proxy.

On mobile and desktop you only need the generator step
(`dart run build_runner build`); there are no worker scripts to compile.

## Publish to GitHub Pages

`.github/workflows/pages.yml` builds the app and deploys it on every push to
`main` that touches the example or the packages (or when run by hand). In the
repository settings, set **Pages > Build and deployment > Source** to
**GitHub Actions** once.

The workflow runs the same steps as above, then
`flutter build web --base-href "/<repo>/" --no-web-resources-cdn`. The base
path matters because the site is served from `https://<owner>.github.io/<repo>/`;
the generated worker URLs are relative to it, so they resolve correctly.

## How the pieces fit

| File | Role |
| --- | --- |
| `lib/workers.dart` | The `@actor`, `@coroutine`, `@encodable` and `@singleton` declarations. |
| `lib/workers.gen.dart` | Generated by `volley_workers_gen` (checked in so the example builds without running the generator). |
| `web_workers/*.dart` | Two-line web worker entrypoints that call the generated `<name>WorkerMain()`. |
| `tool/build_workers.sh` | Runs the generator and compiles the entrypoints to `web/<name>.worker.js`, the default `workerScript` names. |

The worker scripts are build output and are not checked in.

See [`docs/architecture.md`](../../docs/architecture.md) for how the generated
code, the runtime and the web worker protocol work.
